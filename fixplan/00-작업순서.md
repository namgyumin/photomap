## 순서 근거

1. **Part 1 먼저**: 기존 service/타입 구조 파악 없이 코드 작성 금지 (원본 명세 요구사항). COLORS/SPACING 상수가 모든 UI 파트의 기반.
2. **Part 2가 골격**: 3단계 snap 바텀시트 컨테이너 안에 나머지 모든 UI가 들어감. 상태별 표시/숨김 로직(Collapsed에서 사진·탭바 숨김)이 여기서 결정됨.
3. **Part 3→4**: 헤더 → 액션 버튼은 위에서 아래 순서. Collapsed 상태의 전부이므로 먼저 완성하면 Collapsed 상태 검증 가능.
4. **Part 5→6**: 사진 시스템이 가장 큰 신규 기능. 뷰어(6)는 사진 그리드(5) 완성 후.
5. **Part 8은 UI 완성 후**: fetchPlaceDetails 데이터가 헤더(3), 영업시간 카드(7), 통화 버튼(4)에 들어가므로 UI 골격 후 연결. 단, 개발 중 mock 금지 원칙은 처음부터 적용.
6. **Part 9 마지막**: 문서 산출 + `npx tsc --noEmit` + 완료 기준 전체 체크.

## 핵심 불변 규칙 (모든 파트 공통)

- Props interface 변경 금지
- mock data / 하드코딩 값 금지 — 데이터 없으면 UI 숨김
- 없는 아이콘 import 금지 — 텍스트 fallback
- 보기 모드에서 편집 UI 노출 금지
- 기존 연결된 service/API 함수 유지
- 최종 UI는 Google Maps 장소 상세 바텀시트와 최대한 유사
